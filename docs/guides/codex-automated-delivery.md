# Draft-safe automated Codex delivery

## Contract

A background message is a distinct user submission. It never pastes into, clears, reads and restores, submits or otherwise changes the native editor. This holds with an empty editor, an existing draft, concurrent human typing and an active model turn.

Use Codex's existing `thread/queue/add` over its already-running local control socket. Connect only: never start, resume or interrupt a thread, start a daemon, change a model/permission, or fall back to tmux input. The exact current AoE owner and recorded native UUID must agree with the supplied delivery packet, and the owner must be live and unarchived. The selected native store is explicit. Default AoE delivery holds its existing cross-process lifecycle lock through native acceptance, rechecking the stored row so an archive or trash that already won takes no input. Direct standalone operators must coordinate lifecycle changes separately. Codex's standard user-owned control-socket symlink is supported only when its resolved target is an existing user-owned socket; initialization must also confirm the selected native store. A missing socket, thread, supported method or valid identity is a visible failure; preserve the original work and retry state.

Every caller supplies its original stable delivery ID. Different instructions with identical text retain different IDs. A successful result means the native queue accepted the exact text, not that an agent acted on it or completed the work. Preserve the original source IDs, authority, holds and schedule outside this transport. Queue acknowledgment is not an owner receipt: an active long turn can delay actual role=user delivery. The transport does not steer or interrupt that turn, and urgency never permits terminal fallback.

The native queue's `clientUserMessageId` is a correlation ID, not an idempotency guarantee in Codex 0.162.1. Its queue inserts a fresh row on each add. A durable local journal therefore records the exact packet before an attempt, holds a per-ID exclusive lock and records `sending` before the add. A repeated ID with changed text, owner, store or native thread is refused. Confirmed acknowledgments are reused without another add. After an ambiguous failure, reconcile the same ID and text against the native queue or paginated history. Positive evidence confirms delivery; absent or inaccessible evidence leaves an explicit uncertain hold and never re-adds blindly. Definite failures before the add remain safely retryable. A stale journal lock is a visible maintenance blocker, never automatically discarded.

## Operator transport

Native Codex CLI, HTTP and plugin message sends use the same connect-only transport in `contrib/codex-queue-send.cjs`. The CLI requires `--delivery-id`; HTTP and plugin callers supply `delivery_id`. Missing IDs fail before any terminal input or revival. Structured sessions retain their existing daemon transport; other terminal agents retain their current behavior. Inbox answers derive a stable ID from the original ask timestamp and target; plain Inbox messages require their source delivery ID. Native queue acceptance is reported as `queued`; positive history reconciliation is reported as `recorded`. Neither means execution completion.

The transport is embedded in the binary. `AOE_CODEX_QUEUE_HELPER` may explicitly select a reviewed installed helper instead. `AOE_CODEX_QUEUE_STATE_DIR` selects the shared durable journal (default: the AoE application directory under `native-deliveries`); all producers must share it. `AOE_CODEX_WS_MODULE` selects an already-installed WebSocket module (default: `ws`). Missing Node, module, native store, metadata or socket holds delivery. No dependency installation, daemon start, sandbox crossing or terminal fallback occurs. Native Codex aliases and sandboxed sessions are held until their exact supported store mapping is available. Keep existing automation paused until callers propagate stable IDs and these runtime prerequisites are installed and reviewed. Legacy restart wake requests have no original delivery ID: when a nonempty configured wake targets native Codex, refuse that restart before lifecycle changes. Preserve its configured wake text and report the held wake; do not invent an ID, silently drop it or paste it into the restarted editor. An explicitly empty configured wake retains its documented opt-out. Dashboard ask answers derive their source ID from the original ask timestamp and target, reusing it on retry.

The operator supplies a private JSON packet with `sessionId`, `threadId`, `deliveryId` and `text`, a native store, a persistent journal directory, the current profile's sessions file and an existing local WebSocket module. `--check SESSION` performs only initialization, metadata and queue reads. Normal invocation requires `--packet FILE` or `--packet -` with a private packet on stdin; it never creates a packet or invents new execution authority.

The tool emits only receipt metadata and hashes. It never prints message bodies, login material or history. Journal files are private and durably written; journal capacity failure prevents an untracked submission. Test and scratch state belong in the explicitly provided test directory.

## Steering is separate

Codex 0.162.1 also exposes `turn/steer` with `threadId`, required `expectedTurnId`, `input` and optional `clientUserMessageId`. It changes an active turn and returns its `turnId`; review and compact turns can refuse steering. This transport never calls it. Using it would require explicit in-turn authority, exact active-turn verification and its own journal/reconciliation contract. A queue acknowledgment alone cannot authorize steering or interruption.

## Evidence and limits

A successful background message can be pasted into an unfinished human question, with further human typing appended before Enter. This is a composer race, independent of whether the background message is a duplicate. Synthetic editor tests reproduce that symptom with the old tmux primitive and verify the native queue leaves drafts and concurrent typing untouched.

Protocol evidence: the installed Codex 0.162.1 generated schema and upstream [thread queue processor](https://github.com/openai/codex/blob/rust-v0.162.1/codex-rs/app-server/src/request_processors/thread_queue_processor.rs), [queue service](https://github.com/openai/codex/blob/rust-v0.162.1/codex-rs/ext/queue/src/service.rs) and [queue storage](https://github.com/openai/codex/blob/rust-v0.162.1/codex-rs/state/src/runtime/queued_items.rs). Unloaded persisted root threads may accept queue items; existing native queue watchers discover external changes. That is not proof of when a particular message will execute, and no real model message is sent during verification.

## Activation hold

Direct standalone callers still need the same lifecycle guard as default AoE callers. Until that shared gate is verified, activation stays held. Native image input also stays held: a text path is not typed image delivery. Retain the original image payload and source ID; never silently substitute path-only text or remove files referenced by uncertain acceptance. The remaining implementation is one shared lock-owning RPC worker plus typed `localImage` packet paths and hashes checked during acceptance and reconciliation. No live synthetic image or model probe is authorized by this contract.
